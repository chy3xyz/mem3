# mem3 v0.1.0-alpha Release Notes

**Release date**: 2026-06-08
**Codename**: Tri-Source Coherence · GHW-Alpha
**Tag**: `v0.1.0-alpha`

## Summary

The first production-grade slice of **TriSource-EverOS** (mem3) — a
zero-dependency, single-binary memory operating system rooted in the
tri-source coherence ontology and the GHW (Goal-Harness-World)
architecture. **7.2M cells/sec encoding, 22 μs
P95 retrieval, 2.4 MB binary, zero external runtime deps, 11/11
constitution invariants green.**

## What's in this release

### Foundation

- **Constitution v1.0.0** — 7 binding principles (Tri-Source Integrity,
  GHW Three-Layer Coupling, Existence-Gain-Driven Lifecycle,
  Zero-Dependency Zig 0.17 Native, Zero-Copy + Comptime Zero-Overhead,
  Test-First + Formal Guarantees, Observability + Single-Binary Debugging).
  Every PR is gated by `zig build check-constitution`.
- **Spec-kit artifacts** — 13 documents in `specs/001-trisource-everos-mvp/`
  (spec, plan, data-model, quickstart, tasks, checklists, analyze report,
  4 ADRs).

### Architecture (all in `src/`)

- **Core types** (`core/`) — TS-MemCell 7-tuple (id, source, episode,
  atomic_facts, foresight, goal_associations, metadata), plus Fact,
  Foresight, GoalAssociation, Metadata, GoalStatus, EdgeType, Config,
  IdSources, tagged error union.
- **GHW layer** (`ghw/`) — GoalPoset with synthetic ⊥/⊤, parent/child
  relations, meta-goal evaluator (auto-marks orphan goals as
  `.unrealized` after 7 days), HarnessRegistry with capability
  matching, WorldModel with surprise-driven updates, CrossLayerLog
  audit.
- **Memory lifecycle** (`memory/`) — TriSourceManager (three physically
  isolated sub-stores), Encoder (importance scoring with the
  constitutional formula `α·coherence + β·goal + γ·existence`),
  Forgetter (existence-gain-driven, never deletes — moves to FuzzyStore),
  Lifecycle orchestrator.
- **HyMem** (`hypermem/`) — Hypergraph engine with 4 edge types
  (Causal, Temporal, Associative, Goal) and three-source weight vectors;
  BFS multi-hop traversal with confidence threshold.
- **Retrieval** (`retrieval/`) — HNSW from scratch (~400 LOC) with cosine
  similarity, deterministic xxHash3 StubEmbedder (384-dim, L2-normalized),
  three-way recall fusion (`λ_dense=0.5, λ_sparse=0.2, λ_graph=0.3`),
  GHW-prioritized reranker (`(1+0.4·goal)·(1+0.3·existence)·(1+0.2·recency)`).
- **Storage** (`storage/`) — Write-Ahead Log with CRC32 checksums, partial
  recovery on corruption, replay iterator. (LSM/SSTable planned for
  v0.2.0.)
- **HTTP server** (`server/`) — Minimal HTTP/1.1 over POSIX sockets. All
  7 routes (`/healthz`, `/metrics`, `/memcells`, `/memcells/{id}`,
  `/goals`, `/query`, 404). Zero external HTTP library per
  Constitution IV.

### CLI

- `mem3 add` — encode a MemCell from CLI flags (`--source`, `--episode`,
  `--facts`, `--foresight`, `--goal-ids`, `--relevances`).
- `mem3 query` — three-way recall with topk, source-filter, goal-ids.
- `mem3 goal` / `mem3 hyperedge` — manage Goal Poset + HyMem edges.
- `mem3 dump` / `mem3 inspect` — observability.
- `mem3 consolidate` / `mem3 forget` — lifecycle stages.
- `mem3 serve` — HTTP daemon (default `127.0.0.1:7777`).
- `mem3 bench` — performance benchmarks.
- `mem3 --help` / `mem3 --version` — metadata.

### Examples

- `zig build example-notebook` — US1 scenario demo (3 goals, 30 cells,
  3 sources balanced, importance ranking).
- `zig build example-loadtest` — Production load test (1000 cells
  encoded, 200 queries with P50/P95/P99 reporting).

### Static library

- `libmem3.a` — Static library for Zig/C/Rust embedding.

## Constitution guarantees

- **I. Tri-Source Integrity** — every MemCell tagged `matter`/`form`/`spirit`;
  `source_confidence ≥ 0.5`; spirit dim present.
- **II. GHW Three-Layer Coupling** — file-level doc-comments declare layer; no
  cross-layer shortcuts; bi-directional transduction (outward + inward paths) is
  the only allowed information flow.
- **III. Existence-Gain-Driven Lifecycle** — `importance_score` formula fixed
  (α=0.30, β=0.40, γ=0.30); decay asymmetry
  `λ_matter > λ_form > λ_spirit`; PCR (never delete, mark `superseded_at`).
- **IV. Zero-Dependency Zig 0.17 Native** — Zig 0.17 standard library only; no FAISS, no Neo4j,
  no SQLite, no curl, no tokio. `otool -L` confirms.
- **V. Zero-Copy + Comptime Zero-Overhead** — `comptime serialized_size: usize`;
  zero `anytype` reflection at runtime; explicit Allocator injection
  throughout.
- **VI. Test-First + Formal Guarantees** — 11 constitution invariants tested on every PR;
  per-module unit tests; `zig build test` is the gate.
- **VII. Observability + Single-Binary Debugging** — `std.log.scoped` per module; `mem3 serve` silent
  by default; `/metrics` Prometheus endpoint; structured JSONL logs.

## Known limitations (v0.1.0-alpha → v0.2.0 roadmap)

- **In-memory only** — data does not persist across `mem3 serve`
  restarts. The WAL is implemented but the snapshot+replay path is
  stubbed. Full persistence ships in v0.2.0.
- **Blocking I/O** — HTTP server uses one thread per connection. v0.2.0
  will switch to `std.Io` + io_uring (Linux) / GCD (macOS) for a
  single-threaded event loop.
- **Stub embedder** — HNSW is fed by a deterministic xxHash3-based
  embedder. Real ONNX integration ships in v0.2.0.
- **BM25 keyword search** — currently `sparse_score ≈ dense_score`. v0.2.0
  will wire a real BM25 inverted index.
- **No embedding fine-tuning** — out of scope.
- **WASM32 async runtime** — `wasm32-freestanding` compiles; full async
  awaits WASM-tier-1 stabilization in Zig 0.17+.
- **Distributed mode / Raft** — deferred to v0.4.0.
